# go-dydx-indexer

Unofficial Go client for the dYdX v4 Indexer HTTP API. If you only want to use the client from an agent, read [.agents/skills/go-dydx-indexer/SKILL.md](.agents/skills/go-dydx-indexer/SKILL.md) instead; this file is about changing the code.

## Architecture

The client is generated. `make generate` runs `go generate ./...`, which runs the `//go:generate` lines in `gen.go`:

1. `scripts/fetch-spec.sh` downloads `indexer/services/comlink/public/swagger.json` from the `main` branch of dydxprotocol/v4-chain to `api/openapi.json` and checks it has an `openapi` key.
2. `scripts/fix-operation-ids.sh` renames the two operation IDs the spec uses twice (`GET /affiliates/address` becomes `GetAffiliateAddress`, `GET /compliance/screen/{address}` becomes `GetComplianceScreen`) and writes `api/openapi.fixed.json`.
3. `go tool oapi-codegen --config=config.yaml api/openapi.fixed.json` writes `client.gen.go`: models, `Client`, and `ClientWithResponses`.

## Stack

- Go 1.26.9, one package `dydxindexer` at the module root.
- oapi-codegen v2 as a `go.mod` tool, with `github.com/oapi-codegen/runtime` at runtime.
- `config.yaml` maps `number` to `float64`.

## Layout

- `gen.go`: package doc and the generate steps.
- `config.yaml`: oapi-codegen settings.
- `client.gen.go`: generated, never edited by hand.
- `client_test.go`, `example_test.go`: httptest-backed tests and the README example.
- `scripts/`: spec fetch, the operation ID patch, lint and security scan scripts.
- `api/`: the downloaded and patched spec, gitignored, never committed.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec, patch it, regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The repository is AGPL-3.0 (`LICENSE`), not MIT like the other clients, because the generated code derives from dYdX's AGPL-3.0 spec with additional terms (`LICENSE.dydx`). Keep `LICENSE.dydx` and `NOTICE`, and keep `AGPL-3.0-only` in both plugin manifests.
- The spec's only server entry has an empty URL, and its paths start after `/v4`. Base URLs must include `/v4`. The dYdX docs list the testnet HTTP endpoint without it.
- `fix-operation-ids.sh` fails if either renamed path disappears or any operation ID is still duplicated. When upstream fixes the duplicates, drop the matching rename instead of forcing it.
- Decimal values in responses are strings; numeric query parameters without a format become `*float64`.
- The module path ends in `go-dydx-indexer` and the package is `dydxindexer`, so imports need the explicit name or goimports fails lint.
- `scripts/sec.sh` excludes one semgrep rule, the `interface{}` unmarshal check, because oapi-codegen decodes free-form `additionalProperties` that way.
- CI skips the generate drift check, because the spec changes upstream without notice. Regenerate locally and commit the result.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
